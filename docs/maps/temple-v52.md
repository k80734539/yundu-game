# 河神廟重做設計（v52 草案 2）

狀態：**設計草案，尚未實作**。只定規格與路線，不改程式、不生圖。作者看過路線草圖並同意後，才進入實作與生圖。

草案 2 取代草案 1。草案 1 只是把舊庭院放大成十字加直路，玩家仍然只是「走過去、按一下、打一場」，作者回饋「還是太單調」。草案 2 改成三個方向一起做：**地形有形狀、點燈有三種不同方式、有劇情轉折與特殊戰**。

路線草圖：`docs/maps/temple-v52/guide-shore.png`、`guide-court.png`、`guide-hall.png`，總覽 `overview.png`。草圖由 `layout-*.json` 經 `python3 tools/build-temple-guides.py` 產生；要改路線就改 JSON 再重跑，不要手改圖。

## 一、問題（目前線上 v51）

1. 三盞燈籠擠在中央大鼎旁，十秒內做完，沒有探索。
2. 左邊石碑路、右邊石泉路是死路，任務沒用到。
3. 底圖上的石燈本來就畫著火焰，點亮前後畫面幾乎沒差別。
4. 重複點已亮的燈只顯示一個「盞」字：`S.lanternRepeat[i]` 資料格式錯誤（實際 bug）。
5. 整段沒有戰鬥，強度往下掉。
6. 地圖（960×720）比村莊（1344×896）小，容納不了謎題、戰鬥、探索。
7. 草案 1 之後的新問題：路線全是直線與橢圓，每盞燈都是同一個動作。

## 二、設計目標與三個方向

| 方向 | 做法 |
|---|---|
| 地形 | 淺灘兩條路匯合；中庭上下兩層，階梯相連、有迴圈與捷徑；後殿環形走廊繞著神龕 |
| 點燈方式 | 三盞燈三種方式：狐火燒符、扳水閘排水、讀碑選對燈（選錯有代價） |
| 劇情與特殊戰 | 墨刑事件、河伯水影中頭目、九霄雲紋線索、每張圖一個隱藏角落 |

不在範圍：河伯數值、戰鬥畫面、新技能、屬性相剋、戰鬥背景（沿用 `bg_temple`）。

## 三、流程總覽

蘆葦蕩出口 → ① 廟前淺灘 → ② 鎮水中庭 → ③ 水府後殿 → 河伯。

## 四、① 廟前淺灘（`temple_shore`，1344×896）

兩條路在廟門前匯合，玩家選一條，或兩條都走：

| 路線 | 條件 | 內容 |
|---|---|---|
| 淺灘（南） | 免條件 | 會遇到固定戰鬥一次（2 小水妖 + 1 蘆葦精），給經驗 |
| 棧橋（北） | 棧橋有缺口，青舟要用竹篙撐出踏板 | 沒有戰鬥；有舊香碑（環境敘事）與寶箱（魚乾 ×2，key `temple:shore`） |

- 「撐篙架橋」呼應蘆葦蕩的竹篙，這次由玩家自己操作互動，不是看演出。互動後缺口變成可走（`flags.templeShorePole`），踏板由遊戲用程式畫出。
- 隱藏角落：棧橋盡頭的寶箱。

## 五、② 鎮水中庭（`temple_court`，1344×896）

**上下兩層**：下層是水邊（南），上層是石階平台（北），由兩座階梯相連（西、東各一）。上層連成一個 U 形，通往北邊的鎮水門。

三盞燈、三種點亮方式（必須先讀石碑 `flags.steleSeen` 才能點燈）：

| 燈 | 位置 | 方式 |
|---|---|---|
| A | 上層西側凹地 | 被銀雲符封住，**白苓用狐火燒開**才能點亮 |
| B | 下層東側凹地，在淹水區 | **先到上層東側扳水閘**排水，水退後才碰得到 |
| C | 北邊鎮水門兩側各一盞 | **讀碑選對燈**：碑文寫「鎮水之燈在日出之側」，答案是東邊（右）那盞；點錯左邊那盞會引來 2 隻小水妖，打完可重試 |

- 三盞全亮：鎮水門開，同時**中央水道的水退去，露出回到入口的捷徑**（之後來回不用繞路）。
- 戰鬥（固定各一次）：西邊下層 2 隻蘆葦精；東邊上層 3 隻小水妖。因為路線繞來繞去，玩家一定會經過。
- 隱藏角落：上層東北角的凹地，寶箱（清心草 ×2，key `temple:court`），在水閘旁邊。
- 線索：西側石像殘骸上有九霄雲紋（可選對白，呼應第二章下符者伏筆）。
- 疊水區：底圖把淹水區與中央水道畫成**乾的石路**，水由遊戲疊加（半透明水面加波紋），水退時淡出。

## 六、③ 水府後殿（`temple_hall`，1344×896）

**環形走廊繞著神龕**：主路進來後，西側和東側各一條走廊繞到北邊匯合，通往河伯；神龕在環形的內側，從南邊進出。

- 西側室：還願牌（原有內容，可選）。
- 東側室：寶箱（清心草 ×2，key `temple:hall`），隱藏角落，要繞環形走廊才拿得到。
- 神龕旁：銀雲紋（可選對白，和控妖符同一人手筆）。
- **神龕事件**（走近觸發）：
  1. 劇情：控妖符扭曲了鎮水紋，白苓腕上的墨刑靠近時發作，她按住手腕停下來，青舟陪她。
  2. **河伯水影**現身（中頭目戰，`河伯水影`）：HP 約 100、攻擊 12、防禦 3（暫定，數字放 `CFG`）。
  3. 打贏才算削弱封印（`flags.templeSeal`），封印屏障消失，通往河伯的路才開。
- 這張沒有一般小怪戰，用安靜換緊張，然後水影、河伯連續兩場。
- 水影的圖：第一版**不生新圖**，沿用河伯的圖，用程式預先做成偏藍暗的剪影疊色（快取，不用 `ctx.filter`）；若效果不好，再請 Codex 生一組 `heboshadow_*`。

**可選：白苓的墨刑事件加選擇**（陪她，或繼續前進）。這需要新增「對話選項」的介面，目前遊戲沒有。本草案預設**不做選擇，用劇情演出**；若作者要選擇，要另外評估成本。

## 七、燈籠與機關通則

- 狀態仍用 `flags.templeLamps` 位元遮罩：A = 位 0、B = 位 1、C = 位 2，全亮 = 7。
- 水閘：`flags.templeSluice`；水閘扳動後淹水區退水（疊水淡出，區域變可走）。
- 撐篙架橋：`flags.templeShorePole`。
- **生圖時所有石燈畫成熄滅**（沒有火焰、燈芯暗）。點亮由遊戲疊光暈和程式畫的燈焰，前後差別明顯，不用另外生圖。
- **點亮後不再有互動提示、不能再互動。** 修掉 `S.lanternRepeat` 的格式錯誤（若保留重複對白，每項要是整串對白）。
- 每個機關在旅途手札的行程頁與地圖目標列要同步顯示目前步驟，不能出現矛盾。

## 九、舊存檔搬家與重來點

舊存檔裡的地圖 id 是 `temple`：
- 有 `boss` 或 `templeSeal` → 搬到 `temple_hall` 入口；`templeLamps` 設 7、所有戰鬥旗標與 `templeSluice`、`templeShorePole`、`templeHallShadow` 設完成。
- 有 `steleSeen` 或任何燈籠旗標 → 搬到 `temple_court` 入口；`templeShorePole`、`templeShoreFight` 設完成。
- 其他 → 搬到 `temple_shore` 入口。

戰敗重來點：每張圖入口附近（見 JSON 的 `encounters[].checkpoint`），不能卡在戰鬥前或機關前。

## 十、碰撞與實作方式

- 沿用蘆葦蕩 v43 的做法：路線資料（節點、邊、空地）→ 路面聯集 → 腳底六點判定。
- JSON 的邊多了種類：`stairs`（階梯，上下層）、`flooded`（淹水，條件滿足才可走）、`gap`（缺口，撐篙後可走）、`barrier`（屏障，封印削弱後可走）。這些邊「條件未滿足時不可走」，滿足後才加入可走集合。
- 建議把 `src/reeds_map.js` 的邏輯抽成通用的 `layoutMap(layout)`，蘆葦蕩與三張神廟圖共用；`?debug=col` 要一併支援，且要隨機關狀態更新。
- `NAMES` 補三個地圖名；`exitReeds` 改為進 `temple_shore`；原 `temple` id 只留給舊存檔搬家。
- 舊的 `temple_map_v40.webp`、`temple_walk_v44.png` 與 `temple-walk` 測試，等新版穩定後再移除。
- **分階段做，降低風險：**
  1. 先做通用 `layoutMap` 與三張圖的路線、出入口、轉場、舊存檔搬家，**用草圖當暫時的底圖**，把玩法跑起來。
  2. 再做機關（撐篙、狐火、水閘、點燈選擇、鎮水門與水道、水影戰）與測試。
  3. 最後才換成生好的底圖。這樣美術出問題也不會卡住玩法。

## 十一、給生圖的說明（草圖 → 底圖）

三張各 1344×896，**路面位置、寬度、地標位置以草圖為準**：

- 風格：水彩手繪、淡墨線、光源左上、斜視（3/4 俯視），夜景色盤，要跟 `reeds_map_v43.webp` 與現有 `temple_map_v40.webp` 接得上。
- 米色（下層）與淺黃（上層）是可走路面，碰撞寬 48、繪製寬 100；路面以外畫成水、蘆葦、石牆或灌木，**不要讓路面以外看起來能走**。
- 階梯要畫出上下層的高差感。
- **藍色斜線區（疊水區）畫成乾的石路**，水由遊戲疊加。
- 所有石燈畫成熄滅。燈籠位置以草圖為準。
- 淺灘棧橋缺口要畫出斷口，讓玩家看得出需要撐篙。
- 不畫人物、文字、UI。
- 三張要看起來是同一座廟：同樣的石材、屋瓦、苔蘚、水色。
- 每張生完在草圖上疊圖檢查：路面對得上、地標在、出入口可達。

## 十二、測試計畫

## 十四、風險

- **工作量大**：三張圖、通用建圖、四種機關、疊水、水影戰、舊存檔搬家、測試，是第一章修改中最大的一次。
- 疊水、階梯上下層、撐篙架橋、狐火燒符都是新機關，每個要寫程式和測試。
- 三張圖風格一致性取決於生圖，沒辦法預先保證。
- 「乾石路加遊戲疊水」依賴底圖畫得夠乾淨；畫成有水的會跟疊水衝突。
- 舊存檔搬家出錯會讓已有進度的玩家卡關，測試必須覆蓋。
