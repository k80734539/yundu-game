# 河神廟重做設計（v52 草案）

狀態：**設計草案，尚未實作**。本文件只定規格與路線，不改程式、不生圖。作者看過路線草圖、同意後才進入生圖與實作。

路線草圖：`docs/maps/temple-v52/guide-shore.png`、`guide-court.png`、`guide-hall.png`，總覽 `overview.png`。草圖由 `docs/maps/temple-v52/layout-*.json` 以 `python3 tools/build-temple-guides.py` 產生；改路線就改 JSON 再重跑，不要手改圖。

## 一、為什麼要重做

目前的河神廟（`temple_map_v40.webp`，960×720）在玩起來有這些問題：

1. **三盞燈籠都擠在中央大鼎旁**，走過去按三下就完成，十秒內結束，沒有探索。
2. **左邊石碑路、右邊石泉路是死路**，任務完全沒用到它們。
3. **底圖上的石燈本來就畫著火焰**，「點亮」前後畫面幾乎沒有差別，玩家看到的是「燈明明亮著，為什麼要我點」。
4. **重複點擊已亮的燈會出錯**：`S.lanternRepeat[i]` 的資料格式不對，程式把一行對白當成整串，畫面只顯示一個「盞」字。這是實際 bug（v51 已在線上）。
5. **整段沒有戰鬥**：蘆葦蕩有頭目，進了神廟卻直接走向河伯，強度往下掉。
6. 地圖比村莊（1344×896）小，容納不了謎題、戰鬥、探索。

## 二、目標

- 河神廟從一張圖變成**三張各 1344×896 的連續地圖**，節奏為：進場 → 戰鬥 → 探索與謎題 → 戰鬥 → 封印 → Boss。
- 謎題要求玩家**走遍整個中庭**（左路、右路、北門）。
- 燈籠點亮前後在畫面上差別明顯。
- 碰撞用路線資料定義（跟蘆葦蕩 v43 一樣的「路面聯集」），**先有路線、後生圖**，避免再發生「圖和碰撞對不上」。

不在本次範圍：河伯數值、戰鬥畫面、新敵人、新技能、屬性相剋、戰鬥背景（沿用 `bg_temple`）。

## 三、三張地圖

流程：蘆葦蕩出口 → ① 廟前淺灘 → ② 鎮水中庭 → ③ 水府後殿 → 河伯。

### ① 廟前淺灘（`temple_shore`）
- 氛圍：廟的外圍，殘破棧橋、斷掉的石階，蘆葦環繞，香火已斷。
- 路線：入口在左下，一條彎曲的路向右上，中段有一個分岔，終點是通往中庭的廟門口。
- 地標：
  - 西側小凹地：**斷了香火的舊香碑**（一句環境敘事，可選）。
  - 南側小凹地：**寶箱**（魚乾 ×2，key `temple:shore`，可選）。
  - 路中央的開闊處：**固定戰鬥一次**，擋在去中庭的路上。
- 戰鬥：2 隻小水妖 + 1 隻蘆葦精。

### ② 鎮水中庭（`temple_court`）
- 氛圍：把現在的庭院放大重做。十字形：南邊入口、北邊廟門、西邊石碑路、東邊石泉路，中央廣場有一口水井（石鼎）要繞行。
- 地標與機關：
  - 西路盡頭：**石碑**（讀完才能點燈，碑文補一句指出三盞燈的位置）＋**燈籠 A**。
  - 東路盡頭：**石泉**（不可走）＋**燈籠 B**。
  - 北邊廟門左側：**燈籠 C**。
  - 北邊廟門：**鎮水門**，三盞燈全亮才開。
- 戰鬥（各固定一次）：
  - 西路中段：2 隻蘆葦精。
  - 東路中段：3 隻小水妖。
- 因為戰鬥放在左右兩條路上，玩家為了點亮 A、B 一定會打到。

### ③ 水府後殿（`temple_hall`）
- 氛圍：淹水的內殿，神龕與封印，河伯在盡頭。
- 路線：南邊入口往北一條主路，經過神龕，到河伯所在的開闊處；中段有兩個側室。
- 地標：
  - 西側室：**還願牌**（原有內容，可選）。
  - 東側室：**寶箱**（清心草 ×2，key `temple:hall`，可選）。
  - 神龕：**削弱封印**（沿用 `flags.templeSeal`）。
  - 盡頭：**河伯**，封印削弱後交談開戰。
- 這張沒有一般戰鬥，用安靜換緊張，然後直接進河伯戰。

## 四、燈籠機制（重寫）

- 三盞：A（西路盡頭）、B（東路盡頭）、C（北邊廟門左側）。狀態仍用 `flags.templeLamps` 位元遮罩（共 3 位），三位全亮 = 遮罩 7。
- **生圖時所有石燈畫成熄滅的樣子**（沒有火焰、燈芯暗）。點亮的視覺由遊戲疊加：`M.lights` 的光暈加上程式畫的燈焰。這樣前後差別明顯，也不需要為「亮」另外生圖。
- **點亮後不再出現互動提示，也不能再互動。** 玩家走近已亮的燈，什麼都不會發生。
- 必須先讀石碑（`flags.steleSeen`）才能點燈。
- 修正 `S.lanternRepeat` 資料格式的 bug（若保留重複對白，每項必須是「整串對白」，不是單行）。
- 鎮水門的開關由 `templeLamps` 判定，門關著時走近有提示，開了之後門的視覺要變化（至少光源與目標列更新）。

## 五、旗標與存檔

新增旗標（放在既有 `G.flags`，不改存檔格式）：

| 旗標 | 意義 |
|---|---|
| `templeShoreFight` | 廟前淺灘的戰鬥已完成 |
| `templeWestFight` | 西路戰鬥已完成 |
| `templeEastFight` | 東路戰鬥已完成 |

沿用：`steleSeen`、`templeLamps`、`templeSeal`、`boss`、`plaque`、`foundCloth` 等。

**舊存檔搬家**（存檔裡的地圖 id 是舊的 `temple`）：
- 有 `boss` 或 `templeSeal` → 搬到 `temple_hall` 的入口，並把三個戰鬥旗標設為完成、`templeLamps` 設為 7。
- 有 `steleSeen` 或任何燈籠旗標 → 搬到 `temple_court` 的入口，戰鬥旗標設為完成。
- 其他 → 搬到 `temple_shore` 的入口。

戰敗重來點：每張圖入口附近（座標見 JSON 的 `encounters[].checkpoint`），不能卡在戰鬥前。

## 六、碰撞與實作方式

- 沿用蘆葦蕩 v43 的做法：路線資料（節點、邊、空地、橋）→ `walkRects` + 空地橢圓聯集 → 腳底六點判定。
- 建議把 `src/reeds_map.js` 的建圖邏輯抽成通用的 `layoutMap(layout)`，蘆葦蕩與三張神廟圖共用；`?debug=col` 紅框要一併支援。
- `NAMES` 補三個地圖名；`loadMap` 補三個地圖 id；`exitReeds` 改為進 `temple_shore`；原本的 `temple` id 保留給舊存檔搬家用，搬完不再使用。
- 舊的 `temple_map_v40.webp`、`temple_walk_v44.png` 與 `temple-walk` 測試在新版穩定後再移除，不要同時留兩套邏輯。

## 七、給生圖的說明（草圖 → 底圖）

三張底圖各 1344×896，**路面位置、寬度、地標位置以草圖為準**，底圖要貼合草圖：

- 風格：水彩手繪、淡墨線、光源左上、斜視（3/4 俯視），夜景色盤，要跟 `reeds_map_v43.webp` 與現有 `temple_map_v40.webp` 接得上。
- 草圖上米色是可走路面（碰撞寬 48，繪製寬 100）、深藍是水、橢圓是空地。底圖上這些地方要畫成石板路、泥岸、棧橋等，路面以外的地方畫成水、蘆葦、石牆或灌木，**不要讓路面以外看起來能走**。
- 不要畫人物、文字、UI。
- **所有石燈畫成熄滅**（沒有火焰），位置在草圖標「燈籠」的地方。
- 三張要看起來是同一座廟：同樣的石材、屋瓦、苔蘚、水色。
- 每張生完要在草圖上疊圖檢查：路面對得上嗎、地標在不在、出入口可不可達。

## 八、測試計畫

新增 `tests/temple-v52.mjs`（實作時）：
1. 三張圖各自的入口、出口、互動點、燈籠站位都走得到（實際 `update` 移動，不只檢查座標）。
2. 鎮水門在燈未全亮時擋住，全亮後可通過。
3. 燈籠只能點亮一次，已亮的燈不再有互動、不再出現對白。
4. 三場戰鬥各只觸發一次；戰敗回重來點；逃跑不卡關。
5. 舊存檔搬家三種情況。
6. 隨機亂走不會站進擋人處（沿用村莊、河神廟的做法）。
7. `?debug=col` 在三張圖都能顯示。
8. 劇情全流程（`playthrough`）更新為新路線並通過。
